# datumesh-engine 0.2.0 benchmark, 2026-10-24

Same host, database and command as `2026-10-24.md` (0.1.0); datumesh-store 0.3.0. One call at a time from one thread.

Against 0.1.0: the by-reference warm rows are unchanged within noise (each name is now resolved with `resolve_binding`, one query as `resolve_name` was: stored 191 -> 173 µs p50, computed 364 -> 373 µs p50). The rows that sign new receipts are faster, because 0.1.0's `knowable_asof` asked `resolve_name` once more per name read, as of the inputs' asof, for every new receipt, and 0.2.0 takes the binding's start from the lookup it already made: cold computed first ever 6.04 -> 5.53 ms p50, diamond 27.1 -> 19.8 ms, 1,000-deep chain 5.81 -> 4.53 s, graph cold build 58.8 -> 50.1 s, a correction through the graph 29.2 -> 27.1 s. The validated row (2.01 -> 1.60 ms) and the early-cutoff correction (162 -> 212 ms) moved without a change of what they query (no new receipt is signed in them): noise of the shared host. No asof changes in the benchmark (every name is bound before its inputs), and the row counts are the same.
